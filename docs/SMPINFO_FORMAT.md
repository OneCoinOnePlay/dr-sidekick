# SMPINFO0.SP0 — SP-303 Sample Slot Metadata

Status: AUTHORITATIVE
Consolidated: 2026-06-12 (supersedes the legacy toolkit's SMPINFO notes, which
described 512-byte slot records; the verified record size is 48 bytes)

`SMPINFO0.SP0` is the 65 536-byte (64 KB) file on an SP-303 SmartMedia card that
describes the 16 user sample slots (Bank C pads 1–8 = slots 0–7, Bank D pads 1–8
= slots 8–15). It maps each slot to its audio files, records playback settings,
and carries the playback-rate field that selects the sample's RDAC mode.

All multi-byte integers are **big-endian**.

This document describes the structure as implemented in
`dr_sidekick/engine/core.py` (`SlotRecord`, `PadMapping`, `SMPINFO`) and
`dr_sidekick/engine/sp303_codec.py`, validated against hardware-written cards.

## Sequential write log

The SP-303 treats the 64 KB file as an append-only log of 0x400-byte (1 KB)
blocks. Each settings change writes a fresh copy of the full metadata block to
the next 0x400 boundary; earlier blocks are stale history. To find the current
state:

1. Scan blocks at 0x0000, 0x0400, 0x0800, …
2. The first block whose opening 4 bytes are `FF FF FF FF` is unwritten.
3. The block immediately before it is the current state.

Files generated by Dr. Sidekick write only block 0 and fill 0x0400–0xFFFF with
0xFF, so the same reader logic works for both origins.

## Block layout (offsets relative to the current 0x400 block)

| Offset          | Size | Contents |
|-----------------|------|----------|
| 0x0000 – 0x02FF | 768  | 16 slot records × 48 bytes |
| 0x0300 – 0x033F | 64   | Pad mapping table, 16 entries × 4 bytes |
| 0x0340 – 0x035F | 32   | Reserved — all 0xFF (firmware default) |
| 0x0360 – 0x037F | 32   | Reserved — all 0x00 |
| 0x0380 – 0x03FF | 128  | DSP command list |

Everything from 0x0400 to the end of the file is either stale log blocks
(hardware cards) or 0xFF filler (Dr. Sidekick cards).

## Slot record (48 bytes)

Slot *n* starts at offset `n × 48`. Offsets below are relative to the record
start.

| Offset      | Size | Field        | Description |
|-------------|------|--------------|-------------|
| 0x00 – 0x0B | 12   | reserved     | Always zeros (preserved verbatim on round-trip) |
| 0x0C – 0x0F | 4    | sample_len   | Audio data size in bytes (see length semantics below) |
| 0x10 – 0x13 | 4    | loop_start   | Loop point in bytes; equals sample_len for one-shot |
| 0x14 – 0x17 | 4    | sample_end   | Repeat of sample_len |
| 0x18 – 0x1B | 4    | flags        | Power-of-2 duration category (computed; see below) |
| 0x1C – 0x1F | 4    | params       | Two identical copies of the 16-bit params word, always 0x04B0 |
| 0x20 – 0x21 | 2    | rate_field   | Playback rate in tens of Hz — selects the sample mode |
| 0x22        | 1    | const        | Always 0x06 |
| 0x23        | 1    | level        | Sample level, 0x00–0x7F |
| 0x24        | 1    | stereo       | 0x00 = mono, 0x01 = stereo |
| 0x25        | 1    | gate         | 0x00 = normal, 0x01 = gate playback |
| 0x26        | 1    | loop         | 0x00 = one-shot, 0x01 = loop playback |
| 0x27        | 1    | reverse      | 0x00 = normal, 0x01 = reverse playback |
| 0x28 – 0x2B | 4    | const        | Always `00 00 40 00` |
| 0x2C – 0x2F | 4    | const        | Always `03 00 00 00` |

An empty slot has sample_len = 0, flags = `00 00 01 00`, and params bytes
`04 B0 04 B0` (the hardware writes the params template even for empty slots).

### rate_field — sample mode

The rate field stores the playback rate in tens of Hz and is the authoritative
mode selector for RDAC decoding:

| rate_field | Rate       | Mode     | RDAC framing |
|-----------:|------------|----------|--------------|
| 4410 (0x113A) | 44.1 kHz  | STANDARD | 12-byte unit-6 blocks in 512-byte pages |
| 2205 (0x089D) | 22.05 kHz | LONG     | Identical to STANDARD, played at half rate |
| 1102 (0x044E) | 11.025 kHz | LO-FI   | Raw 8-byte unit-4 blocks, no page framing |

LO-FI's true rate is 11 025/… = 1102.5 tens of Hz; the hardware floors it to
1102, so readers must map 1102 back to 11 025 Hz
(`sp303_codec.sample_rate_from_field`).

### flags — duration category

For a populated slot:

```
flags = nearest power of 2 to (sample_len × params_word / 312 500)
```

where 312 500 = 37.5 MHz hardware clock / 120 and params_word is 0x04B0
(= 1200). Verified correct across 55 populated slots from 5 hardware cards
(`core._compute_flags`). Empty slots use the fixed value 0x00000100.

### Length semantics

`sample_len` counts **audio bytes only**:

- **STANDARD / LONG** — sample data files are stored in fixed 512-byte pages of
  504 audio bytes (42 × 12-byte blocks) followed by an 8-byte zero trailer.
  `sample_len` excludes the trailers, so it is a multiple of 504 per full page,
  not of 512. Strip the trailers before block decoding or the 12-byte grid
  slips 8 bytes per page.
- **LO-FI** — no page framing; `sample_len` is the raw block-stream size
  (multiple of 8).

For stereo slots the length applies per channel.

## Pad mapping table (0x0300, 16 × 4 bytes)

Maps physical pad presses to slot indices. Each entry is:

```
[opcode: 3 bytes] [pad_number: 1 byte]   pad_number = 0x01–0x10
```

Dr. Sidekick writes opcode `B0 04 02`; hardware cards have been observed with
variants `04 B0 02`, `04 B0 04`, and `04 B0 08`, all accepted on read. The
default mapping is 1:1 (entry *n* → pad *n*+1).

## Sample data files

Each populated slot references audio files in the card root named by slot index
in **hexadecimal**:

| Slot type | Files |
|-----------|-------|
| Mono      | `SMPnnnnL.SP0` |
| Stereo    | `SMPnnnnL.SP0` + `SMPnnnnR.SP0` |

where `nnnn` is the zero-padded uppercase hex slot index (slot 10 →
`SMP000AL.SP0`). The audio payload is RDAC-compressed; see
`dr_sidekick/engine/sp303_codec.py` for the decoder and framing details.
